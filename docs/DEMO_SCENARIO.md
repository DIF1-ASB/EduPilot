# Демонстрация EduPilot за шесть минут

Перед выступлением: `npm run setup`, `npm run build`, `npm start`. AI_MODE=mock, сеть для учебного цикла не требуется. Заранее создать собственные учётные записи демонстратора без настоящих ФИО детей, класс и одноразовые приглашения. В тренажёре включить «демо-данные», чтобы пробные ответы не смешались с обычной аналитикой. Проверить проектор и reduced motion, при необходимости выключить фон в настройках. Ниже — сценарий, а не утверждение, что репетиция уже состоялась.

0:00–0:40. Показать существующее пространство и созвездие. Сформулировать задачу: объяснять, почему изменяется учебная сложность, и давать учителю наблюдаемый журнал. Сразу сказать: правила детерминированы, AI опционален.

0:40–2:10. Открыть учебную траекторию, математика/дроби, класс7. Показать демо-флаг и пять диагностических вопросов. Для стартового уровня2 дать три верных и два неверных ответа, эталоны брать из банка при подготовке. После каждого ответа показать отдельный разбор до кнопки «Продолжить». Перезагрузить страницу: вопрос/разбор восстанавливаются.

2:10–3:00. Показать подготовленную пробную сессию с серией3 верных/2 неверных. Открыть объяснение перехода и конфигурацию порогов. Не выдавать результат за машинное обучение. Если не успеваете15 ответов вживую, честно использовать ранее сохранённую демонстрационную сессию.

3:00–4:00. Мой прогресс → демо-фильтр: числитель/знаменатель, ошибки, mastery и журнал. Обычная учительская аналитика исключает demo. Для показа её графиков использовать отдельные явно названные демонстрационные аккаунты «Демо ученик» в тестовом классе; эти ручные user-сессии технически обычные, поэтому не публиковать их как реальные педагогические данные. Лучше отдельная локальная база для всего показа.

4:00–4:45. В библиотеке учителя создать демо-черновик, изменить условие, отправить на проверку, отметить ручную проверку, одобрить. Объяснить, что demo даже после одобрения не попадает в обычный банк ученика. Для Live нужен настроенный ключ; качество модели не испытано.

4:45–5:30. Показать `research/results/technical.csv` и `simulation.json`: проверки доступа/гонок и одинаковый банк двух режимов. Симуляция24траектории/360ответов, реальных учащихся0. Продемонстрировать, что показатели не всегда в пользу адаптации.

5:30–6:00. Ограничения: небольшой банк, эвристические пороги, нет данных об эффективности. Показать запланированный самостоятельный pre/post и форму согласия. Закончить практическим результатом: воспроизводимый учебный цикл и проверяемая история решений.

Резерв: локальная production-версия, архив исходников, скриншоты и презентация. При отказе внешней модели продолжить с локальными объяснениями, явно сообщив об ошибке. При отказе браузера показывать заранее снятый интерфейс, не имитировать живые операции. Не вводить и не показывать секреты/API-ключ.
