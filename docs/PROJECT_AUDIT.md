## Приоритеты и технический долг

P0: отдельный детерминированный учебный модуль; атомарная уникальная запись ответа; неизменяемый снимок задания; изоляция владельца и классов; конфигурация алгоритма; минимум 20 повторяемых сценариев. Старые таблицы и миграции не переписывать.

P1: прогресс и аналитика на едином журнале, маркировка demo; AI-рекомендации без ПДн и публикация только после ручной модерации. Наличие ключа не считать доказательством качества/доступности модели.

P2: техническое сравнение с фиксированной последовательностью, протокол будущей педагогической апробации, статья и 10–12 слайдов по реально полученным числам.

Ограничения/долг исходной версии: инициализация RateLimit под конкурентной нагрузкой может сбросить счётчик; QuizSession потребляется отдельно от вставки QuizAttempt; гонка отправки работы с выставлением оценки; ZIP-проверка не ограничивает суммарный распакованный объём. Не менять эти независимые подсистемы без регрессионных проверок. D1 не гарантирует Prisma transactions: новый журнал проектируется через уникальные записи, без зависимости от многошаговой транзакции.

## Принятое решение

Сохранить Next/React, Prisma SQLite/D1, текущую оболочку и созвездие. Добавить `lib/learning`, изолированные API learning, отдельные учебные экраны и добавочную миграцию. Алгоритм — правила, не ML. Пороговые значения — настройки проекта, а не экспериментально оптимальные коэффициенты. Данные симуляций не выдавать за результаты учащихся.

Поля конференции: три автора (ФИО пустые), организация и руководитель пустые; Москва; первый автор — IT-специалист. Эти сведения не дополняются предположениями.
