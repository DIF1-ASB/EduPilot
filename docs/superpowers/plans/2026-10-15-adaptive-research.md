# EduPilot: объяснимый тренажёр и конференционная проверка

Goal: расширить существующий проект, не переписать его; обеспечить автономный учебный цикл, проверяемую аналитику и честные исследовательские материалы.
Architecture: новый модуль learning, журнал turn/attempt с уникальностью ответа, снимки заданий, расчёты из журнала; отдельная добавочная миграция SQLite/D1. AIProvider остаётся серверной границей.
Tech Stack: существующие Next/React/Prisma/Zod/Recharts/Vitest; DOCX/PPTX из фактических результатов.
Spec: пользовательское ТЗ 58e4c751-5843-45d0-b991-6b2336150913, `docs/PROJECT_AUDIT.md`.

## Global Constraints

Существующие записи/миграции/UI сохраняются. Не отправлять ПДн в AI. Никакой фиктивной педагогической эффективности. Три пустых автора, Москва, первый IT-специалист. Настоящий AI без ключа не считается проверенным. Выполнять без повторных разрешений на каждый этап, как прямо потребовано в ТЗ. Рабочая ветка в текущем checkout, не новый проект.

## Review Focus

Гонки параллельных ответов, ответы и снимки не утекают до сдачи, преподаватель видит только своих учащихся, AI draft нельзя опубликовать без проверки, SQL/D1 совместимость, восстановление сессии после сбоя, демонстрационные данные отдельно, большие/невалидные JSON, пороги и границы уровней.

## Task 1: алгоритм и банк

Потребляет: subject/topic/level, history. Производит: типы Question/Evidence, чистые функции диагностики, mastery, решения и выбора. Сначала тесты с буквальными ожидаемыми уровнями/границами/повторами; запустить RED, затем реализация и GREEN. Банк двух предметов с проверяемыми ответами. Коммит после успешного Vitest.

## Task 2: сохранение, API, AI moderation

Потребляет Task1. Производит API catalog/sessions/answer/progress/analytics/tasks/assist. Сначала интеграционные тесты на реальной изолированной SQLite со всеми миграциями: авторизация, resume, параллельные ответы, межпользовательский доступ, непроверенные AI вопросы. RED → миграция + API → GREEN. Проверить неизменность старых данных и генерацию клиента.

## Task 3: учебный UI

Потребляет Task2. Производит `/learning`, progress, analytics, library в прежней оболочке. Добавить E2E перед реализацией; диагностика/ответ/feedback/resume; desktop/mobile, фон выключен/reduced-motion. Проверить typecheck, build и браузер.

## Task 4: воспроизводимое исследование

Потребляет Task1/2. Производит predefined scenarios, JSON/CSV с expected/actual/status и сравнение fixed/adaptive по одному банку. Минимум20 технических сценариев, симуляция явно маркирована. Собирать метрики из реального исполнения, не вписывать числа вручную. Протокол будущей апробации/согласия/формы.

## Task 5: конференционные материалы и итоговая проверка

Потребляет реальные результаты Task4. Производит аудит+отчёт+эксперименты+демо5–7мин+жюри15QA+готовность, статью≤5страниц/7проверенных источников/3новых, 10–12слайдов. Запустить полную проверку, независимый code review, исправить существенное. Обновить запуск и архив outputs. Публикация только существующего сайта в рамках пользовательского запроса.
