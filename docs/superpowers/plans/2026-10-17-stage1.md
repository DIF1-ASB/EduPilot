# EduPilot Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Исправить назначение/выполнение работ, права и оценивание, добавить отдельный конспект и бланк с местом для ответа, сохранив все действующие пользовательские данные на edupilotmfua.ru.

**Architecture:** Три небольших связанных плана с общими контрактами: A — задания/права, N — конспекты, B — бланки. Ни один промежуточный пакет не публикуется на рабочий сервер; выпуск один, после общей приёмки и репетиции миграции на свежей защищённой копии.

**Tech Stack:** Существующие Next.js 16.4.1/React 19, TypeScript, Zod, Prisma 6.19/SQLite, docx/pdf-lib, Vitest/Playwright; Ubuntu VPS, Nginx, systemd и Node 22.23.3 на сервере. Новых платных сервисов нет.

**Spec:** [Утверждённая спецификация](../specs/2026-10-17-assignment-safety-and-notes-design.md), содержание коммита `9fd3287`, утверждение пользователя 17.10.2026. Статус этого плана: подготовлен для проверки пользователем, выполнение ещё не начато.

## Global Constraints

- «Сохраняются все аккаунты, пароли, роли, чаты, материалы, вложения, назначения и результаты».
- «Текущая чистая рабочая копия используется без создания другого worktree».
- «Целевая публикация — VPS edupilotmfua.ru; старый приватный сайт Sites не обновляется, не перепубликуется и не получает копию новых пользовательских данных».
- «По умолчанию: одна попытка, 45 минут, раскрытие только вручную преподавателем и пока не разрешено».
- «Создание презентаций и видео остаётся отключённым».
- «Не используются reset, force-reset, повторный импорт старого сайта или замена базы локальным файлом».
- «Восстановление старой базы не выполняется поверх новых пользовательских записей автоматически».
- Production data: `/var/lib/edupilot/edupilot.db`, `/var/lib/edupilot/storage`; secrets `/etc/edupilot/runtime.env`. Они не входят в исходный архив и не заменяются новой версией.
- Никакие реальные данные не выводятся в чат/логи и не используются в публичных QA-скриншотах. Защищённые копии и manifests — root-only 600/700; вне Git.
- Тесты — на отдельной временной БД и storage, AI_MODE=mock; рабочая БД не получает фикстуры или seed. На VPS допускаются только адресные синтетические smoke-записи с последующим удалением собственных записей.
- Не менять зависимости/lock без необходимости; не переносить Windows node_modules/.next на Linux. Перед продуктовым кодом прочитать локальные Next guides `01-app/03-api-reference/03-file-conventions/route.md` и `01-app/02-guides/self-hosting.md`.

## Review Focus

1. За время разработки появились новые аккаунты/чаты: выпуск использует финальный свежий backup, а не снимок первого переноса или начала разработки — M1/M3.
2. Путь DATABASE_URL неверен или база отсутствует: preflight прекращает выпуск до mkdir/migrate, не создаёт пустую БД — M1/M3.
3. Миграция сохраняет counts, но меняет passwordHash или contentJson: сравниваются все прежние поля и id, а не только количества — M1.
4. Старый код несовместим с новой схемой или уже появились записи после выпуска: автоматическое восстановление старого backup запрещено, новые данные сохраняются перед любым восстановлением — M3.
5. Код работает в mock, но ошибки AI/экспорта/сети оставляют пустые материалы: негативные контрактные тесты N1/A8 и внешние smoke M2/M3 обязательны; реальная AI-квота не используется для массового теста.

## Карта операций и файлов

- `scripts/ops/data-manifest.cjs`: read-only manifest прежних строк и файлов с HMAC, без экспорта содержимого.
- `scripts/ops/rehearse-migration.cjs`: копия backup в новый защищённый каталог, миграция только копии, сравнение и отчёт.
- `scripts/ops/deploy-stage1.mjs`: preflight и управляемый cutover, explicit dry-run/apply, хранение состояния предыдущего release/конфигурации; не содержит паролей.
- `tests/data-preservation.test.ts`, `tests/deployment-guards.test.ts`: запрет неверных путей/потери данных/отката поверх новых записей.
- `e2e/stage1.spec.ts`: совместный синтетический teacher→student→teacher сценарий.
- `../work/stage1-qa/`: синтетические отчёты и визуальные образцы. Реальные backups/manifests не класть в эту публично открываемую папку.
- `../outputs/EduPilot-stage1-implementation-report.md`: итог выполненных проверок, текущий release SHA, время публикации, пути закрытых backup, ограничения без содержимого пользовательских записей.

## Контроль готовности и способ выполнения

До начала выполнения пользователь проверяет этот master-план и при необходимости детали A/N/B. Утверждение спецификации не означает, что этот ещё не просмотренный план уже утверждён. Пока ни один из шагов реализации/миграции не выполнен.

Рекомендация: Native — я выполняю задачи по порядку в этом чате, с TDD, проверками миграции и независимым итоговым review перед выпуском. Это уменьшает повторную передачу сильно связанных контрактов (schema → store → DTO → UI) и расход контекста. Альтернатива — отдельные исполнители и независимые ревью каждой задачи, затем итоговое review; более дорогая схема с дополнительными проверками на границах. После выбора следовать соответствующему execution skill. Независимые агенты сейчас не запускались.
